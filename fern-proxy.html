Fern Proxy

Source in this repo

What it is: Fern proxy is a PostgreSQL proxy. It sits between an app and a database and masks sensitive columns in query results. It is not a web proxy, so it can't unblock websites or games. It also needs a server or Docker, so it can't run on GitHub Pages.

Try it in your browser (simulation)

This is a simulation. A browser can't run the real proxy or open Postgres connections. The two masking strategies below copy the real ones from fern-masking/embedded/src/strategies.rs, and the table is fake data held in this page.


Columns to mask:

Supports SELECT * FROM users or SELECT name, email FROM users. Columns: id, name, email, ssn, city.

Run it (Docker)

This starts a Postgres database, Fern proxy in front of it, and a psql client.

git clone https://github.com/pebbleford/gnmath.git
cd gnmath/fern-proxy/examples
docker-compose up

In a second terminal, connect through the proxy (port 30000, TLS is not supported yet):

docker exec -it postgres-client psql \
  'postgresql://root:testpassword@fern-proxy:30000/testdb?sslmode=disable'

Run a query such as \dS+;. The columns Owner, Name and Access method come back as ****.

Run it (Rust, no Docker)

cd fern-proxy
cargo run --release   # needs Rust 1.63 or newer, listens on port 30000

Then point your Postgres client at the proxy's port instead of the database's own port.

Run it on Oracle Cloud

Oracle's free tier includes Arm VMs (Ampere A1), which are enough for this. Check Oracle's current free-tier limits first. These steps are untested.

  1. In the OCI console, create a compute instance: Ubuntu, an Ampere A1 shape (1 OCPU and 6 GB is plenty), a public IP, and your SSH key.
  2. SSH in and install the tools: 
    sudo apt update && sudo apt install -y build-essential git
curl https://sh.rustup.rs -sSf | sh && . "$HOME/.cargo/env"
  3. Get the code and build it (the first build can take 10 to 30 minutes): 
    git clone https://github.com/pebbleford/gnmath.git
cd gnmath/fern-proxy
cargo run --release
  4. Open port 30000 in two places:
    • In the VCN Security List (or a Network Security Group), add an ingress rule for TCP 30000. Set the source to your app's IP, not 0.0.0.0/0.
    • On the VM, Oracle's Ubuntu images block ports with iptables: 
      sudo iptables -I INPUT -p tcp --dport 30000 -j ACCEPT
sudo netfilter-persistent save
  5. Point your app's connection string at <vm-ip>:30000.

Fern proxy has no TLS yet. Keep the proxy and your database in the same VCN and use private IPs between them, or use a VPN or SSH tunnel. Don't expose port 30000 to the internet.

Shortcut: one command

On the VM, this script does steps 2 to 4 and the VM firewall part of step 5. Read the script before running it. You still add the console ingress rule yourself.

curl -sSLO https://raw.githubusercontent.com/pebbleford/gnmath/main/scripts/setup-fern-proxy.sh
SERVER=<db-host>:5432 bash setup-fern-proxy.sh   # add SITE=1 to also host this site

Choose what gets masked

Edit fern-proxy/examples/config.toml:

[masking]
strategy = 'caviar-preserve-shape'   # or 'caviar' (fixed length)

[masking.exclude]
columns = ['*']                      # leave everything alone...

[masking.force]
columns = ['email', 'ssn', 'card']   # ...except these

Use it with your own app

  1. Run your Postgres server as usual.
  2. Run Fern proxy and configure it to forward to that server.
  3. Change your app's connection string to the proxy's host and port.

The upstream project says it is not ready for production. Use it for demos and experiments.
